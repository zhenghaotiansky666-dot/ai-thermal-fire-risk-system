# FireAegis 前线固件 · 有线优先 + 无线灾备（已验证版）

这是队友交付的 `main.cpp`，我只改了**网络这一段**，感知/报警/BLE 的逻辑一行没动。

## 一、原来为什么有线不通（根因）

原固件里：

```cpp
const char* serverIP = "172.20.10.10";   // 只有这一个地址
const int   serverPort = 5011;
Ethernet.begin(mac);                     // 走 DHCP
```

两个问题叠在一起：

1. **有线和无线共用同一个地址**：`172.20.10.10` 是 Mac 在 iPhone 热点里的地址，网线那条直连链路上根本不存在这个地址，所以有线永远连不上；
2. **直连时没有 DHCP**：板子直接连 Mac 的网线两端都没有 DHCP 服务器，`Ethernet.begin(mac)` 必然分配失败（串口会打印"静态/DHCP分配失败"）。

## 二、改了什么

```cpp
// 无线灾备：Mac 在热点里的地址（和原来一样）
const char* wifiServerIP   = "172.20.10.10";
const int   wifiServerPort = 5011;

// 有线优先：板子直连 Mac 的网线，两端静态 IP、同一网段
const char* ethServerIP   = "192.168.1.20";
const int   ethServerPort = 8787;

IPAddress ethIp(192, 168, 1, 50);        // 板子 W5500 自己的地址
IPAddress ethSubnet(255, 255, 255, 0);
IPAddress noGateway(0, 0, 0, 0);         // 关键：有线不给默认网关

Ethernet.begin(mac, ethIp, noGateway, noGateway, ethSubnet);
```

另外把两次 POST 的重复代码合成一个模板函数 `postTo()`，有线/无线只是目标地址不同；
路由策略没变，仍是**有线优先、连不上自动降级到无线**。

> 为什么要 `noGateway`：如果 W5500 拿到默认网关，它会把默认路由抢过去，
> 于是"降级到 Wi-Fi"那一步发出去的数据也会被塞进网线、直接失败。
> Mac 和板子在同一网段（192.168.1.0/24），同网段通信靠 ARP，本来就不需要网关。

## 三、Mac 端要做一次（只做一次）

直连链路没有 DHCP，Mac 的有线网卡必须手工设成同网段：

```bash
sudo networksetup -setmanual "USB 10/100/1000 LAN" 192.168.1.20 255.255.255.0
```

改完用这条确认：

```bash
ifconfig en7 | grep "inet "     # 应该看到 inet 192.168.1.20
```

恢复自动获取（演示完想还原）：

```bash
sudo networksetup -setdhcp "USB 10/100/1000 LAN"
```

## 四、烧录后串口应该看到什么

```
正在拉通物理有线网口（W5500 静态 IP 初始化）...
【有线】W5500 就绪，本机 IP: 192.168.1.50  目标 Mac: 192.168.1.20:8787
正在并发连通备用无线 Wi-Fi: iPhone
...
常态数据 -> 烟雾值: 489 | 红外最高温: 32.33°C | 有线链路: ON (优先)
【通路：W5500 有线网线】数据已送入 Mac
```

Mac 那边接收端每个请求都会打一行，例如：

```
[19:58:03] POST /upload_thermal ← 192.168.1.50
[19:58:03] POST /upload ← 192.168.1.50
```

看到板子自己的 `192.168.1.50`（而不是热点的 `172.20.10.7`）就说明**这一帧走的是网线**。

## 五、几个提醒

- 网线只协商到 **10baseT（10Mbps）**：能用，但正常千兆/百兆应该是 100M/1000M，
  多半是线材只通了 2 对线或水晶头压得不好，演示前建议换一根成品线；
- 触发阈值现在是 `烟雾 > 200 或 最高温 > 32°C`，很容易触发，适合演示；
- 蜂鸣器只在 Mac 回 `YES` 时才响（这条逻辑我没动）。
