# 硬件同学 · 编辑指南（在最简版系统上接入你的设备）

这份指南对应的是**现在线上运行的那一版**。你要做的只有一件事：
让你的 ESP32-S3 节点能往这台电脑上传数据，并且接收端返回的结果能驱动你的蜂鸣器。

## 二、跑起来（第一次运行）

**macOS**：双击 `启动电脑版.command`
**Windows**：双击 `启动电脑版.bat`

脚本会自动做四件事：

1. 检查 Node.js（没装会提示怎么装）；
2. 第一次运行会 `npm install` + 构建站点（需要联网，只做一次）；
3. 启动**硬件接收端**（默认端口 8787）与**本地站点**；
4. 用独立窗口打开电脑版指挥端（地址里带 `?monitor=1`，进监看模式）。

没有硬件时也可以用模拟器先把链路跑通：

```bash
node tools/hardware-sim.mjs --port 8787 --hot      # 模拟一次高温帧上传
```

## 三、你要改的地方（按重要性排序）

### 1️⃣ 接收端端口（最容易踩的坑）

macOS 的 **5000 端口被系统「隔空播放接收器」占用**，所以我们默认用 **8787**。
端口有三处，改的时候要一致：

| 位置 | 文件 | 说明 |
| --- | --- | --- |
| 站点配置 | `public/ai-config.json` → `hardwarePort` | 页面通过它知道去哪取硬件数据 |
| 启动参数 | `启动电脑版.command` / `.bat` 里的 `HW` | 接收端监听端口 |
| 站点服务 | `tools/local-ai-server.mjs --hardware-port` | 把 `/hw/*` 转发到接收端 |

改成别的端口（例如 5011）时，三处一起改即可。

### 2️⃣ 两个上传路由（固件要对着它们发）

文件：`tools/hardware-receiver.mjs`

| 路由 | 方法 | 用途 | 约定 |
| --- | --- | --- | --- |
| `/upload` | POST | 可见光 JPEG | **必须返回恰好 `YES` 或 `NO`**，固件据此拉响蜂鸣器 |
| `/upload_thermal` | POST | 热像 JSON（`max_temp` + 768 个温度点） | 接收端把它渲染成热像图 |
| `/latest`、`/thermal.json` | GET | 页面读取当前数据 | 带时间戳，用于判断"在线/离线" |
| `/log`、`/health` | GET | 排查用 | 能看到每一次终审结论 |

⚠️ `/upload` 的返回值**不要**改成 JSON 或加换行，固件是按字符串精确比对的。

### 3️⃣ 终审策略（谁说了算）

接收端的判定顺序是：

```
YOLO 视觉服务（若已配置） → 热像最高温阈值（默认 70°C） → 保守返回 NO
```

- 改阈值：启动时加 `--yes-temp 80`；
- 接视觉服务：加 `--vision-url http://127.0.0.1:8000`；
- 只想演示：加 `--always-yes`。

### 4️⃣ 固件里那两行地址

在演示电脑上执行：

```bash
node tools/hardware-receiver.mjs --port 8787 --print-firmware
```

它会用**这台电脑当前的局域网 IP** 打印好可以直接粘贴的两行，例如：

```c
const char* serverUrl        = "http://192.168.1.20:8787/upload";
const char* thermalServerUrl = "http://192.168.1.20:8787/upload_thermal";
```

把这两行替换进固件，Wi-Fi 名称与密码改成现场网络（**ESP32 只支持 2.4G**）。

### 5️⃣ 页面上的硬件面板（可选）

- `src/mobile/HardwareFeed.jsx` —— 电脑端「硬件直连」卡片：两张图 + 最高温 + 终审结论 + 日志；

改完执行 `npm run build`，刷新页面即可看到。

## 四、自检与测试

```bash
node tools/ai-doctor.mjs        # 环境与端口自检（会告诉你哪个端口被占、服务通不通）
npm test                        # 自动化测试（25 个文件、548 条断言）
```

排查顺序建议：

1. `curl http://127.0.0.1:8787/health` —— 接收端活着吗？
2. `node tools/hardware-sim.mjs --port 8787 --hot` —— 模拟器能通吗？
3. `curl http://127.0.0.1:8787/log` —— 最后一次终审是什么、为什么？
4. 页面「监控 → 硬件直连」卡片是否有图、是否显示"硬件在线"。

## 六、常见坑

1. **macOS 5000 被占用** → 用 8787（我们默认就是）；
2. **`/upload` 返回了 JSON** → 固件只认恰好 `YES`/`NO`；
3. **ESP32 连不上 Wi-Fi** → 多数是用了 5G 频段，或热点名里有中文；
4. **页面显示"硬件疑似离线"** → 超过 15 秒没有新数据，检查节点是否还在发送；
5. **两个设备不在同一网段** → 手机热点、校园网隔离都会导致电脑与节点互相看不见，先用同一个路由器验证。
