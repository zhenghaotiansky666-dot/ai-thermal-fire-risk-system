# 软件方向介绍（PPT 素材稿）

> 用途：直接投喂给 PPT，也可作为软件方向对外的统一口径。
> 素材以实际已跑通的演示系统为准，文中数值均来自系统真实设定，不是估算值。

---

## 一句话定位

一套**不装 App、扫码即用**的双端火警系统：系统端一屏完成"看住风险 + 判定火情 + 指挥撤离"，
用户端只做一件事——**告诉你往哪走、还有多远、走哪条楼梯**。

---

## 一、系统端（指挥端）

### 1. 功能总览：六块屏，一条指挥链

| 模块 | 做什么 | 一句话卖点 |
| --- | --- | --- |
| 检测 | 热像图上传 → AI 研判 → 三级预警 | 从"看到高温"到"判定火警" |
| 地图 | 城市级热力与点位分布 | 把单栋楼的火情放进辖区视角 |
| 监控 | 现场视频 + AI 网关 + 硬件数据流 | 视觉、热像、烟感多路证据同时进 |
| 预警 | 报警记录、分区通知、升级策略 | 报警有人接、有人管 |
| 逃生 | 楼宇模型、危险扩散、路线重算、人流负载 | 动态指挥，不是一张死地图 |
| 看板 | 趋势、隐患分布、事件留痕 | 灾后能复盘，日常能排查 |

> 宽屏（≥1180px）自动切换为**电脑监看布局**：左侧竖向导航 + 多列卡片墙，
> 支持一键进入全屏监看模式，适合挂在大屏上当值守终端。

### 2. 三阶段 AI 决策链（对应"火灾前 / 中 / 后"）

- **阶段一 · 火灾前预防判定**
  视觉（火焰、烟雾）+ 热像 + 烟感三路证据融合，输出**判据得分、置信度、有效证据路数**，
  决定"要不要报警"，并自动生成给周边居民的通知文案。
  实测演示：判定火警 / 判据得分 47 / 置信度 75% / 有效证据 2 路。
- **阶段二 · 起火时动态救援**
  汇集用户端二元问答的上报结果（楼层、位置、是否需要帮助），
  配合 3D 楼栋模型给出起火位置、封控通道与楼内现况，让救援端"进门之前就知道楼里什么情况"。
- **阶段三 · 火灾结束后搜救**
  红外扫描残余热场，识别人体温度特征，给出**优先排查顺序与置信度**，辅助后续救援。

### 3. 多源证据融合（区别于"单看一路视频"）

- 火焰与烟雾置信度来自视觉通道，热像来自硬件通道，二者**都进入同一套决策链**，不是各显示各的。
- 单点传感器被遮挡、误报时，其余通道可以兜底；多路同时确认才升级为火警。
- 证据带**时效**（8 秒），过期证据自动失效，避免"烧完了还在报警"。
- 支持**多火源**：多个起火点同时标注，逃生路线会同时避开。

### 4. 3D 可视化：能点进楼层，也能缩放定位

- 校园微缩模型接入系统，全景展示建筑分布与真实相对位置。
- **点选楼层即可切入楼层视角**，看到该层平面与火源所在位置。
- 定位到起火楼层时**动态放大**到对应楼层，一眼看清"火在几楼、哪一侧"。
- 火源在模型中以脉冲高亮显示，支持多火源并存。

### 5. 硬件接入：Wi-Fi 和网线都能进

- 接收端固定 **8787 端口**，开放 `/upload`（可见光）与 `/upload_thermal`（红外热像）两条路由。
- 双通道：Wi-Fi 直连，或 **W5500 网线接入**（有线优先，抗火场信号干扰）。
- 每帧数据都记录**来源 IP**，指挥端可直接判断这一路走的是网线还是 Wi-Fi。
- 预留全部传感器接口，AI 模型只需按约定格式接入，不改前端。

### 6. 报警联动：系统端一按，用户端同步响

- 系统端触发火警演练，用户端**同一时刻收到预警**，无需用户任何操作。
- 通知内容包含起火楼层与具体位置，不是一句"着火了"。
- 两级升级策略：默认 30 秒未确认则提高音量、加快播报，可配置或关闭。
- 报警与处置全程留痕，可导出处置报告。

### 7. 可量化的运行数据

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 平均响应时间 | 1.8 秒 | 从判定到下发预警 |
| 中高风险占比 | 23.8% | 用于巡检优先级排序 |
| 导航路线重算 | 1 次/秒 | 火势与人流变化即时跟随 |
| 证据有效期 | 8 秒 | 过期自动失效，抑制误报 |
| 信标定位有效期 | 90 秒 | 超时自动回退手动选点 |
| 未确认报警升级 | 30 秒 | 默认升级策略，可配置 |

## 二、用户端（逃生指引）

### 1. 使用流程：三步，零学习成本

1. **扫码**——扫系统端二维码，直接进入本次演练/真实火警，不用下载、不用注册、不用登录。
2. **看表盘**——屏幕中央一个指南针表盘，只给三个读数：**往哪个方向走、还有多远、走哪条楼梯**。
3. **跟着走**——按箭头走到楼梯口，到下一层自动切换；需要时切到 AR 实景，箭头直接叠在真实走廊上。

### 2. 便捷性设计（这一页就是用户端的核心竞争力）

- **无需安装**：浏览器打开即用，可"添加到主屏幕"当 App 使用；评委现场扫码即可体验。
- **单屏极简**：沿用 iOS 指南针的交互思路，一个大表盘、极少按钮，恐慌状态下也能一眼看懂。
- **全自动接管**：收到火警**自动弹出全屏报警**（红色高对比 + 警笛 + 语音播报 + 震动），
  用户不需要去找设置、点开关。
- **位置零输入**：楼道蓝牙信标自动定位并刷新路线（走过一个新信标就重算一次）；
  信标失效或没有信号时自动回退到手动选点，功能不中断。
- **实时改道**：路线每秒重算；A 梯、B 梯、正门、天台任一被封，立刻绕行，并优先向下撤离。
- **大字跟随模式**：屏幕跟随手机朝向转动，只看箭头不看字也能走。
- **AR 实景导航**：摄像头画面叠加方向箭头，直接指向安全出口，不依赖看平面图。
- **AI 二元问答**：紧急情况下 AI 只问"是 / 否"，例如"你现在能自己走动吗"，
  答案自动汇总给救援端，既降低用户负担，也让救援端掌握楼内人员分布。
- **离线兜底**：网络中断时可用离线码/本地规则继续给出逃生方向，不因断网变成一块白屏。

### 3. 用户端保留的传感器接口

位置（信标 / 手动）、火情、热像遥测、手机朝向、报警设置等输入统一收口到一层。
原生 App 只要按同样的键名与数据结构写入，Web 端即时生效，**不需要改这一层**——
这也是用户端能持续接入更多传感器、让楼道导航越来越准的原因。

## 三、两端怎么联动（建议做成一页示意图）

```
硬件（相机 + 热像 + 烟感）
        │  Wi-Fi / 网线 W5500
        ▼
   接收端 8787（/upload、/upload_thermal）
        │
        ▼
   系统端：多源证据融合 → AI 判定 → 3D 定位到楼层 → 一键下发
        │                                     │
        │                                     ▼
        │                         用户端：全屏报警 + 方向指引
        │                                     │
        ◄──────  用户状态与问答结果回传救援端  ──────┘
```

一句话讲清：**硬件负责看见，系统端负责判断，用户端负责把人带出去，三端共用一份事实。**
