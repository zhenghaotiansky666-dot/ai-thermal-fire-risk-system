# 网线接入（W5500 以太网）· 远程接口说明

> 这一篇解决的就是"最后差的那个网线接口"：**让节点通过网线把数据送到电脑端**。
> Wi-Fi 那条链路已经通了；网线这条除了硬件插上，还需要**电脑端知道该用哪张网卡的地址**，
> 以及**固件侧往哪发**。下面都配好了。

---

## 一、电脑端：先确认"有线网卡是哪一张"

**第一步：把 USB/雷雳 网线适配器插上，并确认它拿到了 IP。**
macOS：系统设置 → 网络，看到多出一条"USB 10/100/1000 LAN"之类的已连接设备即可。

**第二步：让接收端自己报告。**

```bash
node tools/hardware-receiver.mjs --port 8787
```

启动后会打印本机所有网卡，并标出类型：

```
  本机网卡：
    en0      10.244.141.95    无线
    en5      192.168.1.20     有线     ← 网线接入用这个
```

**第三步：直接生成给固件的地址（推荐）。**

```bash
node tools/hardware-receiver.mjs --port 8787 --print-firmware --medium ethernet
```

它会自动挑**有线那张网卡**，打印两行固件地址 + 一段 W5500 初始化片段。
如果当场没插网线，它会明确提示"没有检测到有线网卡"，并用占位符，避免你把无线地址抄进固件。

也可以手动指定：

```bash
node tools/hardware-receiver.mjs --port 8787 --print-firmware --interface en5
```

---

## 二、固件侧：W5500 要加的东西

W5500 走 **SPI**，接好后在固件里加三步（其余逻辑不用改，仍然是往 `/upload` 和 `/upload_thermal` 发）：

```cpp
#include <SPI.h>
#include <Ethernet.h>

byte mac[] = { 0xDE, 0xAD, 0xBE, 0xEF, 0xFE, 0xED };

void setup() {
  // W5500 的 SPI 引脚按你们的接线填（CS 用哪个 GPIO 就填哪个）
  Ethernet.init(/* CS 引脚 */);
  Ethernet.begin(mac);            // 插上网线后自动 DHCP 拿地址
  // 自检：串口打印本地地址，确认在同一个网段
  Serial.print("wired ip = "); Serial.println(Ethernet.localIP());
}

// 发送时把 HTTPClient 换成 EthernetClient（URL 换成 --print-firmware 打印的有线地址）
EthernetClient client;
if (client.connect(host, 8787)) {
  client.println("POST /upload_thermal HTTP/1.1");
  client.println("Host: <电脑有线网卡IP>");
  client.println("Content-Type: application/json");
  client.print("Content-Length: "); client.println(payload.length());
  client.println();
  client.print(payload);
}
```

要点：

1. **引脚不要和相机/热像模块抢**。MLX90640 用 I2C、相机用并口/高速 GPIO，W5500 的 SPI 另找一组空闲脚；原来的固件里 GPIO 2 / GPIO 4 同时被相机和 I2C/烟雾传感器占用，是我标出来的待确认项，接 W5500 时一起理顺。
2. **网段要一致**：电脑有线网卡和节点都拿到同一路由器/交换机的 DHCP（例如都是 `192.168.1.x`）。
3. **`/upload` 的返回值必须恰好是 `YES` / `NO`**，固件据此拉响蜂鸣器——网线这条路也一样。

---

## 三、怎么验证"网线真的通了"

1. 电脑上先启动接收端：`node tools/hardware-receiver.mjs --port 8787`
2. 节点通过网线通电，串口应打印 `wired ip = 192.168.1.xx`
3. 电脑上点一下接收端健康检查：`curl http://<有线网卡IP>:8787/health` → 返回 `{"ok":true,...}`
4. 节点发一帧后，接收端会打印：
   ```
   [upload] 257.8 KB → YES（thermal：热像最高温 85.4°C（阈值 70°C））
   ```
5. 系统端「监控 → 硬件直连」卡片上会显示**来源 IP**——这就是判定走没走网线的依据：
   - `来源 192.168.1.xx` = 网线进来（有线网段）
   - 无线网段的地址 = Wi-Fi 进来

## 四、如果节点和电脑不在同一网段（真正的"远程"）

上面是"同一个局域网、走网线"。如果节点接在另一个网段（例如校园有线网，而电脑在 Wi-Fi），
它连不到电脑的私网地址，这时用**站点代理**这条路：

- 电脑端跑本地站点后，节点把数据 POST 到**站点的同源代理**：
  `http://<电脑IP>:4173/hw/upload_thermal`
- `/hw/*` 会把请求原样转发给接收端（我们已确认支持 POST 与二进制体），
  页面上的"硬件直连"卡片读的也是同一条数据；
- 站点的 `/sync` 中继还能让另外一台电脑（评委机）同时看到这份数据。

> 注意：这仍然要求节点能访问到电脑的地址。真要跨网段、跨网络推送，需要把接收端放到公网
> （我们已有的 `tools/relay-worker.mjs` 可以扩展成硬件入口），那是下一步，先在局域网把网线这条路跑通。
